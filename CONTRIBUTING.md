# Contribuir a VeMtas

## Regla principal

No cambiar invariantes financieras o de seguridad sin un ADR.

## Flujo recomendado

1. crear issue;
2. crear branch;
3. implementar cambios pequeños y verificables;
4. añadir tests;
5. abrir PR;
6. documentar cambios;
7. fusionar únicamente cuando las verificaciones estén correctas.

## Código

El proyecto debe priorizar:

- tipos explícitos;
- validación en backend;
- idempotencia;
- observabilidad;
- pruebas de invariantes;
- secretos fuera del repositorio.

## Codex

Las tareas para Codex deben incluir:

- objetivo;
- archivos/módulos afectados;
- restricciones;
- criterios de aceptación;
- tests obligatorios;
- documentación a actualizar.

No pedir implementaciones abiertas del tipo “haz toda VeMtas”.
